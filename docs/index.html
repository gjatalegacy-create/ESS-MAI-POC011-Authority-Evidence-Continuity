Authority, Evidence and Durable Continuity

A small Rust experiment in distinct executive competences: retain missing evidence and counterexamples, refuse unsupported actions, and admit an evidenced action without duplicating its local recorded effect.

Distinct competences, one evidence-bound flow

The proposed AI Authority paradigm organises work around a defined duty, independent executive competence, jurisdiction and governing law. An authority performs its own work; permission or refusal follows from that work. GCL denotes the constitutional order, not an extra executive authority or voter.

Several calls may fulfil different competences. QUANTUM proposing an action and SHADOW verifying it are different responsibilities, even when they inspect the same values. A new cycle may exercise a competence again with current checks. Counting calls does not establish duplicated authority.

  1. LIGHT coordinates: bind the current input, context and candidates; retrieve bounded references to earlier records in that context.
  2. QUANTUM reasons: compute the finite model, retain gaps and counterexamples, eliminate inadmissible candidates and propose an eligible action.
  3. SHADOW verifies: recompute the current case and check its trace and RAM receipt. Spine checks precede Matrix; mandatory gates are conjoined, not averaged or voted upon.
  4. Commit, then return: consume the local one-use admission slot, commit the report and optional effect, flush, synchronize and read back. Publish the new memory state, release transient processing, then return output and questions.

D-BAB witnesses actual preconditions before the corresponding operations and outcomes afterward; it neither grants authority nor vetoes another competence. 0-NOI supplies a neutral borrowed trigger, while the caller retains its checks.

Missing evidence is a recorded gap, not a scientific refutation. The successful cycles retain the inadmissible competitor and its counterexamples. Cycle 4's approval does not authorize cycle 5.

The effect is a local record of model values. Repeating the same context/action/value adds no second effect; conflicting values refuse commit. These are capsule status names and scalar bits, not the native paired (0,0)/(1,1) protocol or universal native authority semantics.

Reproduce locally

Clone the public capsule. Use Rust 1.99.1 and Python 3 for the separate verifier. The maintained branch also tests Rust 1.98.0 and current stable; see the compiler compatibility correction and CI evidence. The original v0.1.0 archive retains its Rust 1.98.0 requirement. Offline execution requires the pinned Cargo dependencies in your local cache; on a clean machine, first run cargo fetch --locked with network access.

git clone https://github.com/gjatalegacy-create/ESS-MAI-POC011-Authority-Evidence-Continuity.git
cd ESS-MAI-POC011-Authority-Evidence-Continuity
cargo test --locked --offline
cargo test --locked --offline --release
cargo run --locked --offline --release -- demo demo-run
cargo run --locked --offline --release -- inspect demo-run/memory.wal
python tools/verify.py demo-run --self-test

demo-run must not already exist. The demo creates five input files, five cycle-output files and a journal. Cargo creates build artifacts; tests use isolated temporary files. Inspection reads and locks the journal without admitting a new action. No private AIGovern-Cyber runtime is required.

Mathematical selection is deterministic. Timing measurements and dependent receipt hashes may differ between runs. Reproduction and critique protocol.

Boundaries that remain explicit

  • The trusted boundary includes the program, host and local storage. SHA-256 and the 500 seal are integrity links, not signatures or proof of issuer identity.
  • An older valid journal prefix can be substituted without detection when all storage is controlled. Readback and synchronization do not prove physical power-loss recovery.
  • The RAM write/readback is real process-owned memory work. It does not measure physical energy, DRAM residency or thermal safety, and its timer is not hard real-time enforcement.
  • Single-use handle consumption protects a particular local admission, not the definition or transfer of executive competence. The C-ABI probe is internal, not a separately compiled external C client.
  • No external exactly-once effect, complete native KiS/KiC pipeline, complete authority hierarchy, universal once-per-cycle authority invariant or VERITAS integration is demonstrated.

The proposed use as a governing core in other systems remains a research direction. Reproducible objections, unsuccessful cases and attributed contributions are welcome. AI-assisted implementation was used under the author's architecture and direction; the recorded checks remain distinct from independent validation.
